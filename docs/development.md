# 开发与数据说明

本文记录插件当前的目录结构、运行数据、缓存机制和诊断方式，供维护者排查问题。说明以仓库现有代码为准。

## 主要目录

```text
index.js                     插件入口、指令处理和定时推送
lib/weather.js               地点解析、天气数据源适配与字段标准化
lib/precipitation.js         逐小时降水时间窗口、提醒筛选与事件去重
lib/alerts.js                气象预警获取、区域汇总、缓存和后台刷新
lib/alert-place-cache.js     预警地点映射持久化缓存
lib/admin-divisions.js       行政区划数据加载、校验和自动更新
lib/preferences.js           会话偏好与提醒设置存储
lib/settings.js              天气数据源与 WeatherAPI Key 设置存储
lib/subscriptions.js          每日天气订阅存储
lib/view.js                  天气、帮助和预警图片的视图数据
lib/help-content.js          帮助图片文案与分类
resources/                   HTML 图片模板和内置行政区划数据
docs/                        项目配置、开发及数据源说明
test/                        Node.js 内置测试运行器的自动化测试
```

项目采用 ES Modules。`package.json` 声明 Node.js `>=23.11`，测试命令为 `npm test`；项目未声明额外 npm 运行依赖。

## 持久化数据

数据默认保存在 `data/weather-panel/`。该目录包含会话配置、订阅、服务密钥和缓存，不应提交到公开版本库。

| 文件 | 用途 |
| --- | --- |
| `preferences.json` | 默认城市、主题、降雨/降雪/预警开关、早晚报时间及推送去重状态 |
| `subscriptions.json` | 每个机器人会话的天气订阅城市、时区、推送时间及当日发送状态 |
| `settings.json` | 全局天气来源与 WeatherAPI Key |
| `geocoding-cache.json` | 通用城市解析结果，默认有效 90 天、最多 1,000 条 |
| `admin-divisions.json` | 下载并校验后的行政区划数据 |
| `admin-divisions-meta.json` | 行政区划数据版本日期及下次更新信息 |
| `alert-cache.json` | 单地点预警快照，默认有效 5 分钟 |
| `alert-region-cache.json` | 省、市级预警汇总及其覆盖、时间状态 |
| `alert-place-cache.json` | 按行政区划代码保存的成功地点映射和明确未命中的负缓存 |
| `alert-active-regions.json` | 最近查询区域的持久化记录，用于恢复有限的后台刷新计划 |

预警单地点缓存、汇总缓存、地点映射和一般地名解析缓存相互独立。天气预报结果没有跨请求的持久缓存。图片缓存只保存在进程内存中。

## 地点映射与负缓存

- 中国境内天气地点优先通过 MSN/Bing 地点搜索解析；境外地点使用 Open-Meteo 地理编码，未匹配时回退 Photon。国内查询不会因解析失败而回退到无法可靠区分地级市与区县的 Photon 结果。
- 使用 Photon 成功解析的地点会在天气卡片数据来源处标注 Photon 和 OpenStreetMap 署名。Photon 是公共服务，可能限流或暂时不可用。
- MSN 预警地点映射按行政区划代码及层级校验；成功映射默认有效 180 天，明确未找到的地点默认负缓存 24 小时。
- 地点解析失败、网络失败和查询到空预警是不同状态。负缓存只表示地点暂时无法解析，不代表地区无预警，也不算覆盖成功。
- 同一地点的并发地点解析会共享进行中的任务；省、市、县级汇总可复用已缓存的映射。
- 普通地名解析结果单独写入 `geocoding-cache.json`，与预警地点缓存使用不同的有效期和数据结构。
- 可以使用 `#刷新天气地点缓存 地区` 强制重新解析一个地区，或使用 `#清理天气地点缓存` 清理地点解析记录。指令权限和参数见[高级配置](configuration.md)。

## 预警区域汇总与覆盖率

省级汇总读取该省行政区划节点下的目标地区；地级市汇总读取对应下属地区；区县查询按数据源返回的实际地点查询。MSN 地点搜索无法定位或请求失败的目标会记为失败/未覆盖，不会从统计中消失，也不会被作为无预警处理。

汇总快照记录查询范围、成功/失败/未查询数量、数据来源和最后成功获取时间。遇到部分失败时返回部分覆盖状态；超过缓存有效期但仍可作为历史快照的结果会标注历史状态，不表示当前预警仍生效。若数据源没有返回下级行政区域的预警集合，单点查询不会被冒充为全省或全市汇总。

### 缓存、后台刷新与请求合并

- 单地点预警及区域汇总默认缓存 5 分钟。
- 活跃区域默认在最后一次查询后的 45 分钟内保留后台刷新计划，最多记录 10 个区域；缓存到期前默认提前 90 秒启动刷新。
- 后台只处理近期用户查询过的区域，不会在插件启动时扫描全国。重启后恢复仍在有效期内的区域记录。
- 同一地区的前台与后台刷新共享任务；区域扫描有全局及单次并发限制，默认均为 3、上限为 5，并按主机限制请求间隔。
- 网络错误按有限次数退避重试；HTTP 429 按响应的 `Retry-After` 延迟后再处理。失败刷新不覆盖上次成功快照。
- 汇总缓存默认可继续保留最多 24 小时作为历史快照；页面会显示其历史状态和实际数据时间。
- 普通天气图片内存缓存默认 3 分钟，最多 40 张且总大小不超过 64 MiB；预警图片默认 5 分钟，容量限制相同。内容、主题、来源时间或覆盖状态变化会形成不同缓存键。
- 更多超时、缓存期限及并发配置见[高级配置](configuration.md)。

行政区划数据默认每 180 天检查更新；失败后使用现有本地数据，至少 24 小时后再重试。自动更新可由 `WEATHER_ADMIN_DIVISION_AUTO_UPDATE=0` 关闭。

## 诊断与常见排查

### 省、市级预警覆盖不完整

查看日志中的 `[天气插件预警地区]` 记录，可按地区查看解析状态、缓存命中、请求状态、耗时及失败原因。`[天气插件性能]` 汇总记录覆盖数量、请求数量、缓存命中和查询/渲染耗时。覆盖不完整通常表示部分地名未被 MSN 识别、数据源不支持或请求未成功；应按实际统计解释，不要把失败地点算成无预警。

### 后台刷新或缓存未恢复

查找 `[天气插件预警后台刷新]`、`已恢复 ... 个近期活跃预警地区` 与 `[天气插件] 预警缓存初始化失败` 日志。确认机器人进程对 `data/weather-panel/` 有读写权限，并检查 JSON 文件是否可解析。损坏或无法读取的缓存会被跳过或安全重建；首次查询可能重新产生网络请求。

### 天气图片无法生成

检查宿主环境的图片渲染器是否可用，并查看 `天气卡片渲染失败`、`帮助图片渲染失败` 等错误。普通天气图片在主模板渲染失败时会尝试文字版天气图片；天气查询所需数据仍须能从选定来源获取。

### 天气源或 API Key 问题

使用 `#天气源` 查看当前来源及 WeatherAPI Key 是否已配置；机器人主人可私聊设置密钥。不要公开原始请求日志或配置文件；日志和请求 URL 即使经过脱敏，也应在分享前检查是否含有敏感值。

### 自动化测试

使用项目自带的 Node.js 测试运行器执行：

```bash
npm test
```

测试覆盖天气字段标准化、提醒阈值与去重、预警覆盖和缓存、地点映射持久化、配置存储及帮助指令解析。
